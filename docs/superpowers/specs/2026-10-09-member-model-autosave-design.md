# 团队模型菜单：逐成员下拉框与选择即保存

日期：2026-10-09

## 已确认的需求

用户已在布局预览中选择方案 B（选择即保存）：顶部固定设置新成员默认模型，下方每个现有成员直接使用自己的模型下拉框，删除全局「设置对象」下拉框。

本规格记录该方案的交互与安全边界，供用户审查；此阶段不实施生产代码改造。

## 布局与可编辑范围

- 保持插件自有、锚定标题栏按钮的非模态弹出菜单，不进入或修改官方团队菜单内部。
- 顶部是「新成员默认模型」，不归属于任何成员；支持选择完整模型路线或「继承原设置」。
- 每个可编辑的 teammate 成员卡片直接展示模型下拉框；模型支持推理等级时，展示该成员自己的推理等级下拉框。
- 不再出现「设置对象」下拉框、常规「保存」或「取消修改」按钮。
- 成员卡片保留名称、状态、最近使用模型及待下轮生效的模型概要。
- 保持现有权限边界：running 和 inactive 成员均可编辑；创建中、失败成员显示不可编辑原因；不新增 Lead 模型编辑能力。
- 菜单适应当前视口，成员较多时内部滚动，不改变现有关闭与焦点恢复机制。

## 选择即保存

- 模型下拉框每次有效变更立即提交，只修改该卡片对应的目标；不要求再次点击保存。
- 切换模型时将推理等级重置为「模型默认」，将完整 provider/model 路线一并提交，不沿用旧模型的推理等级。
- 推理等级变更单独立即提交当前完整路线；选择「模型默认」时不携带 reasoningEffort 字段。
- 顶部选择「继承原设置」时提交 null，清空并禁用推理等级选择。
- 无效、不可路由或没有完整 provider/model 的值不可提交；没有实际变更时不重复写入。
- 初次展示以已保存默认模型或成员 nextModel/currentModel 为初始值；后台轮询不得触发自动保存。

## 生效语义

- 新成员默认模型仅影响之后创建的成员，不批量改动现有成员。
- 成员模型选择提交成功后，最早在该成员下一轮 turn 开始时生效，不修改当前轮中的后续查询。
- 「已保存」仅表示设置提交得到确认；「最近使用」依旧展示最近实际执行时的模型，不能被乐观改写。

## 保存中的互斥与状态

- 复用现有设置 Controller 的全局保存互斥，不增加并发写队列。
- 任一目标保存期间，禁用整个菜单的模型与推理下拉框，防止并发请求被 Controller 拒绝。
- 当前目标显示「保存中」；只有该目标显示提交结果，其他成员的选择不被改写。
- 保存期间沿用现有禁止关闭规则，包括按钮切换、Escape、外点及关闭按钮。
- 保存成功后以 RPC 返回的已提交视图确认状态并解除锁定；其他卡片不因该次保存重置。
- 轮询和目录更新不得覆盖正在保存或失败后待重试的目标选择；目录变化导致路线不可用时显示对应原因，不静默替换模型。
- 没有正在提交或待重试选择的目标，随最新已提交视图同步下拉框；这种同步不触发写入。

## 失败与重试

- 提交失败时在对应目标处显示明确的失败状态、错误信息及「重试」操作；该操作是恢复失败提交，不是常规保存按钮。
- 保留用户失败的选择用于重试，不误显示为「已保存」或已经生效，同时解除全局保存锁。
- 用户可改选其他有效模型；新的选择替代该目标待重试的选择。
- 失败后的后台读取可更新已提交概要，但不能把未确认的本地选择混同为已提交状态；不假设失败意味着服务端已回滚。
- 成员离开、变成不可编辑状态或会话切换后，旧目标不可继续提交或重试；旧请求结果不可进入新会话的 UI。
- 模型目录加载错误依旧是菜单局部、可重试的错误，不使标题栏入口退席。

## 架构边界与保留修复

- 使用独立目标编辑器实例隔离各成员和默认设置的状态；目标身份使用稳定成员 ID，RPC 仍使用成员不可变名称。
- 每个目标通过现有 Controller 和插件自有 RPC 提交；不新增业务 RPC、后端存储格式或官方团队运行时改造。
- 保留之前的 Lead 引用租赁、等待 ready、取消与释放逻辑。
- 保留本轮已修复的 remote.session 精确依赖声明，不退回渲染时同步解析目录，不绕过 Cordis 注入保护。

## 验收与测试

1. 菜单没有设置对象选择器；顶部与每个可编辑成员同时显示自己的下拉框。
2. 变更默认、任一成员模型或推理等级，均自动发送且仅发送对应目标的完整提交。
3. 成员之间的选择不串扰；后台轮询不覆盖待保存选择，也不产生写入。
4. 保存中禁用输入及关闭；提交成功解除锁定，失败可见且允许重试。
5. 切换模型清除旧推理等级；继承仅作用于未来成员且提交 null。
6. 覆盖 inactive 可编辑、创建中或失败态不可编辑、成员消失和会话切换。
7. 保留真实 Cordis/SDK 冷目录构造回归、缓存复用及引用释放测试。
8. 严格类型检查、全量测试、生产构建和包契约检查通过；不将 fixture 集成测试声称为真实浏览器 E2E。

## 交付边界

实现并验收后再生成包含新布局的独立安装包。不覆盖已有修复包，不在运行中的 Agent Team 上热替换 profile。开发工作区构建不自动更新当前 GUI；部署后仍需在空闲维护窗口更新、冷重启并刷新，实际成员页另行确认。
